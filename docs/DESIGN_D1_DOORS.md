# 설계: D1 데모에 문 토큰·탐험 이동 옮기기 (초안, 2026-10-23)

> 실험 페이지(`prototype/door_lab/`)에서 확인한 **P1 문 토큰 + 탐험 이동**(`docs/DESIGN_DOORS.md` 8~13절)을 D1 데모(`prototype/d1_demo/`)에 옮길 때의 설계서.
> 코드는 아직 안 고침. 총괄 초안이고, 아래 "정해야 할 것" 표를 사용자가 고르면 `core-dev`·`frontend`에 맡긴다.
> 전제: HANDOFF "다음 할 일 ①" **5×7 판 실험이 성공**해야 시작한다. 숫자(문 수·통과 한도·이동 속도)는 그 실험 결과로 정한다고 적어 둔 곳이 있다.

## 0. 한 줄 요약
판을 "여러 칸 덩어리 구역 + 정해진 다음 구역(EXITS)"에서 **"칸(방) + 문 토큰"**으로 바꾸고, 침입자 길은 **분대마다 탐험 경로를 미리 계산**해서 경로 미리보기·전투력·실제 전투가 **같은 계산**을 쓴다. 시설·대기실·부대·마석·납품 흐름은 그대로 둔다.

## 1. 지금 D1과 실험 페이지의 차이
| 항목 | 지금 D1 (`zones.js`) | 실험 페이지 (`lab.js`) | 옮긴 뒤 D1 |
| --- | --- | --- | --- |
| 판 | 5×7, 구역 = 2~4칸 덩어리 (`BOARD_DATA` map) | 3×4, 1칸 = 1방 | 층마다 **5×7**, 기본 1칸 = 1방, 고정 구역만 여러 칸 |
| 길 | `EXITS` (위→아래 한 방향, 판에 고정) | 문 토큰 (양방향, 플레이어가 옮김) | 문 토큰 |
| 갈림 | 점수(미끼 +2, 몬스터 든 대기실 -1)가 같은 쪽으로 **번갈아** | 안 가 본 방 → 미끼 → 습관 60% → 나머지 무작위 (시드 고정) | 실험 규칙 그대로 |
| 되돌아가기 | 없음 | 맵핑: 아는 방들로 가장 짧은 길 | 실험 규칙 그대로 |
| 미리보기 | `forecast` (사람 단위) | `routesOf` (분대 단위, 전투와 같음) | 분대 단위 하나로 통일 |
| 함정 | 들어설 때 + 안에 있는 동안 `TRAP_EVERY`초마다 | 방에 들어갈 때 1번, 같은 분대 최대 2번 | D1 방식 유지 + **같은 함정은 같은 분대가 2번 들어갈 때까지만** |
| 속도 | `MOVE_SPEED` 0.32칸/초 (1칸 ≈ 3.1초) | 방 하나 2초, 가 본 방 1.5배, 처음 방 조사 0.6초 | 조사·1.5배 추가, 속도는 6절 |
| 층 | 1층 5×7 + 2층 5×4(`mini2`) | 1층만 | 층마다 5×7, 계단으로 이어짐 |

## 2. 판 데이터 모양
### 2-1. 칸 id와 방 id
| 것 | 규칙 | 예 |
| --- | --- | --- |
| 칸 id | 층 번호(1층은 생략) + 열 글자 `A`~`E` + 행 숫자 `1`~`7` | 1층 `C4`, 2층 `2C4` |
| 입구 칸 | 맨 위 가운데. 방 id는 지금처럼 `E` / `2E` | 1층 `C1` → 방 `E` |
| 보물방 칸 | 맨 아래 가운데. 방 id `B` / `2B` (2층이 열리면 1층 `B` = 계단) | 1층 `C7` → 방 `B` |
| 1칸 방 | 방 id = 칸 id | `B3` |
| 고정 구역 (여러 칸) | 방 id = 판 데이터에 적은 이름, 칸 여러 개 | `FZ1` = `B4`·`C4`·`D4` (얼어붙은 하역장) |
| 야외 | `Y` 그대로 (침입자 대기 장소, 문 없음) | |

- `site.zones`(방 → 시설)·`site.units`(대기실 → 부대)의 **키가 방 id**라서 지금 코드의 "구역 id" 자리에 그대로 들어간다. 이름만 `R2`·`CD` 같은 글자에서 칸 좌표로 바뀐다.
- 칸 좌표가 id라서 화면이 따로 지도 없이도 그릴 수 있다. 사람이 읽을 이름(`NAMES`)은 "3열 4행" 대신 **"가운데 4"**처럼 짓는다(입구·보물방·고정 구역은 지금 이름).

### 2-2. 판 정의 (`battle_data.js` 또는 `zones.js`의 새 표 `GRID_BOARDS`)
```js
GRID_BOARDS: {
  g1: {                       // 첫 의뢰 판 (1층)
    name: '얼음 하역장 길', desc: '...',
    rooms: { FZ1: ['B4', 'C4', 'D4'] },   // 여러 칸 방만 적음. 나머지 칸은 저절로 1칸 방
    fixed: { FZ1: 'frozen_dock' },        // 고정 구역 시설 (지금 quest.fixed와 같은 뜻)
    doors: ['C1-C2', 'C2-C3', ...],       // 처음 문 배치 = 문 토큰 수 (판마다 고정)
    blocked: []                           // (나중) 문을 못 놓는 벽. 데모는 비움
  },
  g2a: { ... },               // 2층 의뢰 1층
  g2b: { ... }                // 2층 의뢰 2층 (칸 id 앞에 '2'는 끼울 때 붙임, 지금 mini2와 같은 방식)
}
```
| 칸 | 뜻 |
| --- | --- |
| 벽 조각(edge) id | 이웃한 두 칸 id를 **정해진 순서**(위→아래, 왼→오른)로 `-`로 이음: `C2-C3`(세로 이웃), `B3-C3`(가로 이웃). 2층은 `2C2-2C3` |
| 문 | 벽 조각 하나에 열린 통로. **서로 다른 방 사이 벽에만** 놓을 수 있음 (고정 구역 안쪽 칸 사이 벽은 벽 조각 목록에서 뺌) |
| 계단 | 층 사이 고정 통로: 위층 `B` → 아래층 `2E`. 문 토큰이 아니고 판 바깥 규칙(지금 `makeLayout`의 계단 잇기 그대로) |
| 판 바깥 벽 | 문 못 놓음 (입구 위쪽만 야외와 이어짐) |

- **의뢰 데이터**: `QUESTS[].board`가 판 id 하나 대신 **층별 판 목록** `boards: ['g2a', 'g2b']`를 가짐. 문 토큰 수는 층마다 따로 (2층 문을 1층에 못 옮김).
- 처음 문 배치는 **손으로 설계**하고 selftest로 "모든 방이 입구와 이어짐 · 통과 한도 안 · 가능한 이동이 여러 개"를 증명(실험 페이지와 같은 기준).

### 2-3. 시설은 그대로, 크기만 바뀜
- 1칸 방이 기본이라 `perCell` 비용·가치·함정 피해(`TRAP_PER_CELL`)·대기실 자리(`DEN_SLOTS_PER_CELL`)가 **방 하나 = 1칸 값**이 된다. 지금 2~4칸 구역보다 시설 하나가 작아지고 시설 수는 많아짐 → 마석·납품 기준은 다시 재야 함 (8절 위험 3).
- 입구 시설 `wait`·`left`·`right`(전원을 한쪽으로)는 문 퍼즐과 겹치므로 **없앰**(입구는 늘 `split` = 아무 효과 없음). `thorn`(덫 숲)은 데모에서 이미 꺼져 있음.

### 3-1. v7 (새로 늘어나는 칸)
| 칸 | 모양 | 뜻 |
| --- | --- | --- |
| `v` | `7` | 판 모양이 바뀌어서 올림 |

## 4. battle_sim에 탐험 이동 넣기
### 4-1. 길 계산은 zones.js 한 곳 (`exploreRoute`)
- 실험 페이지 `exploreRoute`·`chooseCandidate`·`mappedReturn`·`seededRandom`을 **거의 그대로** `zones.js`로 옮긴다. 입력: 문 목록, 시설(미끼 위치), 출발 방(층 입구), 목표 방(그 층 `B`), 분대 번호, 시드.
- **층마다 따로 탐험**: 1층 입구 → 1층 `B`. 2층이 열려 있으면 `B`(계단)에 닿는 순간 2층 입구 `2E`로 내려가 **가 본 방 기록을 비우고** 2층 탐험. 경로 = 두 층 경로를 이은 것.
- 분대 습관: D1 분대 번호 `i`(0부터) → 습관 `i % 3` (왼쪽·오른쪽·아래). 무작위는 실험처럼 **분대·방·갈림 순서로 만든 시드** → 다른 분대·미리보기에 영향 없음.
- 같은 배치 + 같은 `plan.seed` = 같은 길 (실험 페이지 12절 확정 그대로).

### 4-2. battle_sim.js 바꿀 곳
| 곳 | 지금 | 바꾼 뒤 |
| --- | --- | --- |
| `create` 분대 길 | `Z.routeOf(zones, units, turn)` | `Z.exploreRoute(doors, zones, i, plan.seed)` → `steps`(`from`·`to`·`edge`·`backtrack`) |
| 지나갈 점(`wps`) | `doorOf`(구역 사이 맞닿은 칸 **추정**) + `anchorOf` | `doorPoint(edge)` = **문이 놓인 벽 조각 가운데**(추정 없음) + 방 가운데. 되돌아가는 걸음도 같은 방식 |
| 처음 방 조사 | 없음 | 처음 들어간 방에서 `INSPECT_TIME`(0.6초) 멈춤. 사건 `{ type:'inspect', id, z }` (화면 `?` 표시) |
| 이동 속도 | `MOVE_SPEED` × 카드·하역장 | × **1.5** (다음 방을 이미 가 봤거나, 지금 방이 빈 대기실일 때) |
| 함정 | 들어설 때 + 머무는 동안 굴림 | 같은 분대가 그 함정 방에 **3번째부터 들어가면 굴리지 않음** (`q.trapIn[z]` 셈) |
| 대기실 | 산 몬스터 있으면 멈추고 몇 초 동안 공방 | **조우 즉시 승패 판정** + 말풍선 1초·1초 (11절, 사용자 확정). 되돌아오며 다시 들어가도 부대가 남아 있으면 또 조우 |
| 문 통과 셈 | 없음 | `q.passes` (결과·디버그용). 한도를 넘는 배치는 애초에 확정이 안 되므로 전투에서 막을 일 없음 |
| 진행도(`prog`) | 지나간 거리 ÷ 경로 길이 | 그대로 (경로 길이에 되돌아가는 길 포함) |
| 위기 treasure | `Z.bossFront()`(보물방 바로 앞 구역) | **보물방과 문으로 이어진 방**들 (문을 옮기면 바뀜) |
| `snapshot`/`restore` | `q.wps` 등 | 그대로. `o.doors`를 `create`와 같게 넘김 |

- 몬스터 든 대기실을 "보여서 피함"(-1)은 탐험 규칙에 없다 → 9절 질문 1.
- 탐험은 전투 중 일(몬스터 처치·퇴각)에 따라 길을 바꾸지 않는다(실험과 같음). 그래서 **미리 계산한 경로 = 실제 경로**가 보장된다.

### 4-3. 전투력(B안)·문 위 숫자도 같은 계산으로
| 것 | 지금 | 바꾼 뒤 |
| --- | --- | --- |
| 통과 비율 `passRatios` | `forecast` 600명 사람 단위, 층 입구 기준 | **고정 시드 M개 × 습관 3 = 경로 3M개**를 탐험 계산. 방 비율 = 그 방을 지난 경로 수 ÷ 3M. 층 입구 기준 그대로 |
| 함정 점수 | `trapScore × 비율` | `trapScore × (경로마다 min(들어간 횟수, 2)의 평균)` → 막다른 방 왕복이 점수에 보임 |
| 대기실 점수 | `부대 점수 × 비율` | 그대로 (비율만 새 계산) |
| `forecast()` | `{ at, flow }` | 모양 그대로, 값은 같은 경로들에서 셈 (`flow` 키 `'C2>C3'`). 화면은 `?debug`에서만 씀 |
| `mustPass()`(튜토리얼 강조) | 판 모양 | 문 그래프에서 "빼면 입구→보물방이 끊기는 방" (문을 옮기면 바뀜) |

- M은 전투력 미리보기가 흔들리지 않게 **고정 시드**(예: 1~4). 실제 전투는 `plan.seed` 하나 → 전투력은 "평균 기대값", 전투는 "그 주 한 번" (지금과 같은 관계).
- 계산량: 방 35개 너비 우선 탐색 12번 = 가벼움. 다만 `previewBuild`를 칸마다 부르는 곳(build.js 밝게 할 칸 고르기)은 지금처럼 `light` 모드로 피함.

### 11-3. 같이 생각할 것
- 대부분 이기면 매주 전투의 재미는 승패가 아니라 **"내 함정·대기실이 침입자를 어떻게 처리했나"**에서 나와야 함 → 결과표 한 줄("함정으로 2분대 퇴각, 대기실에서 1분대 격퇴")을 이번에 같이 넣는 것을 제안.
- battle_sim 바꿀 곳: `fightDens`(공방) → 조우 판정 함수 하나, 사건 `{ type:'clash', id, z, win, t }`(화면 말풍선), 침입자 퇴각 사건, `result`에 퇴각·격퇴 수. `RETREAT.burstWindow`·`bigShare`·`deathChance`는 데모에서 안 씀.
- 5×7 실험 페이지에서도 같은 판정(조우 즉시·2초)으로 재면 D1에 옮길 때 숫자가 맞음.
