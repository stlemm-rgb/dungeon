# UI·탭 구조 개편 — 한 쪽 기획서 초안

> 2026-10-28 · **확정 기준:** `refs/debate_ds_restructure_2026-10-28.md`의 최종 수렴 1~6. 아래 세부 배치는 제안이며 10절에서 선택한다.
> 참고: `refs/ref_dungeon_sisters.md`, `prototype/d1_demo/API.md` 15절, `shell.js`, `HANDOFF.md`, `docs/GAME_STRUCTURE.md` 1·2절, `facility_upgrade.md`. 옛 문서의 5탭·다음 주·가치/전투력 납품 조건보다 최종 수렴이 우선한다.

## 1. 왜

현장을 메인으로 삼아 일반 침입 관전 → 배치 수정 → 보스 재도전을 한곳에서 잇는다.
회사에는 계약과 인물, 군단에는 보유·영구 성장을 모아 다음 행동을 찾기 쉽게 한다.
첫 의뢰 한 바퀴를 완료선으로 삼아, 1인 개발에서 화면 개편이 콘텐츠 확장으로 번지는 것을 막는다.

## 2. 화면 전체 틀

| 영역 | 늘 보이는 틀 | 화면마다 바뀌는 내용 |
| --- | --- | --- |
| 상단 바 | 회사 레벨·현장 전투력, 관련 재화, 설정, 다음 목표 한 줄 | 회사 = 회사 금, 현장 = 마석·회사 금, 군단 = 신석·회사 금. 의뢰가 없으면 전투력은 `—`, 가짜 0이나 전체 군단 합계를 쓰지 않음 |
| 본문 | 선택한 탭의 내용 | 회사는 의뢰·인물, 현장은 같은 판 4상태, 군단은 목록·상세. 보스 검증 막대는 현장 본문 머리에 고정 |
| 하단 탭 | **회사 · 현장 · 군단**, 순서·이름 고정 | 선택 표시만 변경. 행동 버튼으로 바꾸지 않음. 군단은 첫 전투 정산 전 `잠김 · 첫 전투 후 열림` |

제안: 현장 밖에서는 일반전을 멈추고 현장 복귀 때 이어 간다. 보스 도전 중에는 탭을 보이되 이동을 막고 `보스전 종료 후 이동`을 표시한다. 의뢰 없는 현장에는 회사의 의뢰 게시판으로 가는 안내만 둔다. 정산·데모 끝은 회사 본문으로 모으고, 처리 중인 정산이 있으면 그 화면을 먼저 복원한다.

390×844 기준 상단 약 88px·하단 탭 56px와 기기 안전 여백을 확보한다. 남은 본문에서 판 비중은 운영 약 60%, 건설 75%, 보스 도전 70%, 결과 45%를 시작점으로 잡는다. 고정 비율보다 **판 전체·주요 버튼 노출**을 우선한다. 긴 목록만 따로 세로 스크롤하고 버튼은 그 아래 고정한다. 창을 열면 선택한 방을 가리지 않게 판과 창 영역을 나눈다.

## 3. 현장 4상태

| 상태 | 판(위)에서 보일 것 | 아래 판에서 할 일 | 들어오고 나가는 버튼 |
| --- | --- | --- | --- |
| 운영 | 일반 침입 한 판씩 자동 반복, 시설·문·분대·남은 시간 | 최근 정산 한 줄, 다음 보스 예고, 배속·일시정지, 시설 누르면 강화 상세 | 현장 진입/일반 침입 재개 → 운영. [건설] → 건설, [출진] → 현장 안 편성 창, 큰 [보스 도전] → 보스 |
| 건설 | 멈춘 같은 판을 크게, 방·벽·문·미확정 배치 강조 | 시설 띠·문 토큰·철거/교체, 비용·환급·오류 이유, 확정/취소 | [건설] 또는 결과의 [배치 고치기]로 진입. [건설 확정]/[취소] → 원래 운영 또는 결과로 복귀 |
| 보스 도전 | 해당 단계 고정 침입자, 보물방·남은 시간, 전투 사건 | 배속·일시정지, 보스 이름·단계. 후속 카드 자리는 여기만 | 운영의 [보스 도전], 결과의 [다시 도전]/[다음 보스 도전]. 종료 시 결과로 자동 전환 |
| 보스 결과 | 마지막 판, 분대별 도달 위치·선택한 기록의 방 강조 | 성공/실패, 함정 피해·퇴각 원인·첫 성공 보상. 실패 벌칙 없음 | 실패: [배치 고치기][다시 도전][일반 침입 재개]. 성공: [다음 보스 도전][일반 침입 재개]. 5/5: 다음 도전 대신 [납품] |

**적용 경계(확정):** 건설 중 전투 정지, 수정안은 현재 판이 끝난 뒤 적용한다. 강화·성장·출진도 같은 경계이며 `다음 판부터 적용`을 붙인다. 수정 중인 판과 실제 전투 배치를 구별하고, 일반전을 재개해 기존 배치로 정산한 뒤 수정안을 반영한다. 보스 예약 시에도 진행 중 일반전을 마친 뒤 수정안을 확정하고 보스를 시작한다. 판이 없으면 바로 적용한다. 건설 취소는 이번 수정만 버리며 비용을 쓰지 않는다. 미확정 상태에서 탭/뒤로 이동은 확정·취소 선택으로 처리한다.

**현재 구현과의 차이:** API 15절은 변경 시 일반전을 버리고, `challengeBoss()`도 일반전을 즉시 끊는다. 따라서 위 경계는 **저장·경제 단계에서 수정안 보관·판 정산 후 적용을 먼저 연결할 요구사항**이다. 지금 함수만으로 이미 되는 기능으로 보지 않는다. `flowInfo()`·`bossInfo()`·`questProgress()`로 상태를 읽고, `applyBattle()`의 결과를 한 번만 반영한다. 재도전은 같은 단계 시드, 성공 보상은 최초 한 번, 닫지 않은 결과는 새로고침 후 복원한다.

## 4. 회사 탭

- **의뢰 없음:** 의뢰 게시판을 첫 영역으로, 후보의 부지·보상·수락 버튼을 표시한다. 잠긴 후보에는 실제 해금 조건을 붙인다. 수락 → 현장 운영으로 이동한다. 인물 무대·터치 대사는 아래에 유지한다.
- **의뢰 있음:** 첫 영역은 의뢰 이름·보스 검증 요약·[현장으로], 아래는 기존 사무실 인물과 작품집. 게시판 상세는 계약·보상 확인용이며 보스 도전 버튼을 중복 배치하지 않는다.
- **납품:** 실제 [납품] 실행 입구는 현장 5/5 결과 하나. 회사에는 `검증 완료 · 현장에서 납품` 안내만 둔다. 현장에서 실행하면 회사의 납품 정산으로 이동해 보상·인계/유지 내역·친위대 지정·작품 등록을 보여 준다. [정산 마치기] → 데모 끝. 5/5 결과를 닫았어도 현장에 돌아오면 납품 가능한 결과로 복원한다.

## 5. 군단 탭·성장 창

제안: 하위 탭은 **부족 · 친위대**. 부대장은 확장 자리만 설계하고 이번 데모에는 숨긴다. 친위대는 `잠김 · 첫 납품 후 열림`으로 보여 주며 납품 뒤 확인 가능하다. DS 동료 화면의 선택 목록→상세 구조만 가져온다.

목록은 그림·이름·레벨·보유/사용권 상태를 2열 카드로 보여 주고, 선택 시 아래 상세를 연다. 부족은 역할·현재/다음 강화 효과·신석 비용, 친위대는 출신·능력치·경험치와 `1층 C3 출진 중 / 대기` 요약을 표시한다. 출진 배치를 바꾸는 버튼은 군단에 두지 않는다. 현재 미구현인 친위대 강화 버튼도 만들지 않는다.

**성장 창 공통 표시:** 대상 → 지금/다음 효과 → 비용이 적힌 실행 버튼 하나. 시설은 `이번 현장만`, 부족 강화·친위대 보유는 `계속 유지`를 붙인다. 잔액·부족 이유·최고 단계·적용 시점은 버튼 옆, [닫기]는 같은 자리다. 닫기만 하면 변경 없음. 건설·출진·카드는 각자 조작 방식을 유지한다.

같은 변경 기능의 실행 입구는 한곳에 둔다. 안내 링크는 해당 자리로 이동만 한다.

| 데모 끝·처음부터 다시 | 회사 데모 완료 화면 | 유지, 작품집·군단 확인 가능. 재시작은 기존 초기화 동작 |
| 뒤로/닫기·잠김 이유·오류 토스트 | 각 상세의 원래 탭/상태 | 유지, 미확정 처리·보스 이동 제한이 우선 |

## 7. 상단 바·단계 막대·다음 목표 문구

전투력은 참고 수치이며 납품 조건처럼 그리지 않는다. 막대는 **성공한 보스 수 n/5**, 도전 중인 번호는 별도 표시한다. 재화 이름은 회사 금·마석·신석으로 통일하고 해당 화면의 것만 노출한다. 다음 목표는 `행동 + 대상` 한 줄, 우선순위는 정산/납품 → 미확정 수정 → 실패 후 수정 → 다음 보스다. 근거 없는 자동 추천이나 성공 보장은 하지 않는다.

| 상황 | 상단 바 예시 | 단계 막대 | 다음 목표 한 줄 |
| --- | --- | --- | --- |
| 첫 운영 | 현장 전투력 100 · 회사 금 80 · 마석 100 | 보스 검증 0/5 · 다음 1단계 | 첫 보스에 도전해 방어를 확인하세요 |
| 2단계 실패 | 현장 전투력 100 · 회사 금 80 · 마석 90 | 보스 검증 1/5 · 2단계 실패 | 보물방에 도달한 길의 배치를 고치세요 |
| 최종 성공 | 현장 전투력 120 · 회사 금 120 · 마석 60 | 보스 검증 5/5 · 검증 완료 | 납품하고 회사에서 정산하세요 |

## 8. 데모 범위 / 안 할 것

이번 범위는 첫 의뢰·기존 시설/문·출진/강화·군단 보유/성장·보스 5단계·납품·친위대 지정·작품집·데모 끝을 새 동선으로 연결하는 것이다. 순서는 **흐름 시험 폰 확인 → 저장·경제 → 이 구조의 UI 구현 → 카드 → 2층·q2**. 카드·2층은 자리 시안만 확인하고 지금 기능을 켜지 않는다.

DS에서 가져오는 것은 상단 바·다음 목표·하위 탭·잠김 조건·성장 표시 규칙이다. 보유효과, 카드 수집·뽑기, 상점, 마계 지도, React 전환, 방치 보상, 새 재화, 수치 밸런스 확장은 하지 않는다. 미구현 입구 숨김은 10절 제안이며, 데모에서 못 여는 하단 탭 숨김은 확정이다.

## 9. 끝 기준

- **동선:** 새 게임 → 회사 수락 → 현장 건설/출진 → 일반 침입 → 같은 보스 실패 → 문 수정 → 재도전 성공 → 5/5 → 납품·친위대 지정·정산 → 데모 끝. 군단·작품집도 확인 가능하며 중복 실행 입구가 없다.
- **상태:** 수정안은 판 경계에 적용, 취소·닫기는 무차감, 보스 중 변경 금지. 탭 이동·뒤로·새로고침 뒤 배치/일시정지/결과가 보존되고 보상·납품은 한 번만 처리된다.
- **화면:** 390px 폭에서 4상태·강화/편성 창·말풍선을 확인한다. 판·선택 방·닫기/주요 버튼이 가려지지 않고 가로 넘침 0, 콘솔 오류 0. 긴 결과 목록에도 행동 버튼이 보인다.
- **검사:** 구현 완료 시 새 동선에 맞춘 D1 흐름·화면 검사와 `py tools/check_all.py` 통과. 이 문서는 기획 초안이며 아직 구현·플레이 검증 결과가 아니다.
