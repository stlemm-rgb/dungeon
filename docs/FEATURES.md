흩어진 기능·콘텐츠를 한 줄씩 모아, 다음에 무엇을 만들지 고르는 지도다.
GAME_PLAN = 결정 일지 · CONTENT_IDEAS = 아이디어 창고 · FEATURES = 무엇을 언제 만들지 지도.
단계 용어: 데모 → (비공개 테스트) → 출시(스토어 정식, 과금 포함) → 나중(업데이트). 배포는 이 모두를 내보내는 일이다.
데모 범위는 사용자 10-24 결정으로 두 번째 현장까지(2층 판·두 번째 의뢰 포함)다. 현재 구현은 1층 첫 의뢰 납품 후 끝(q2 숨김); 끝인 항목의 출시는 출시에도 유지할 기반이라는 뜻이며, 구현 상태는 최신 HANDOFF를 우선한다. 출시 최소 범위는 의뢰·건설·군단 성장부터 완성하고, 내 집·지점은 나중으로 둔다.

## 구현 대기열 (데모, 사용자 10-24~25)
> 상태 순서: 아이디어 → 초안 있음 → **기획 확정** → 만드는 중 → 끝. 구현은 Claude 토큰이 많이 들어 시작 전에 사용자에게 묻는다.

| 순서 | 기능 | 상태 | 맡을 곳 |
| --- | --- | --- | --- |
| 1 | 시설 강화 | 기획 확정 | core-dev(로직) → frontend(화면) |
| 2 | 던전 카드 개편 (이벤트·출진·원군 3종) | 기획 확정 | core-dev → frontend |
| 3 | 첫 현장 특별 현장 (마석 200 시험 등) | 일부 확정(시설 강화 ⑥) | 1·2 뒤 측정하며 |
| 4 | 전투 결과 설명 + 화면 다듬기 2차(건설 판 가시성·결과표 [홈으로]) | 아이디어 → 기획서 필요 | 솔(기획서) → frontend |
| 5 | 2층 판 + 두 번째 의뢰 | 설계 있음 (`docs/DESIGN_D1_DOORS.md`) | core-dev → frontend |
| 뒤로 | 튜토리얼·스토리 장면 초안 | 기능 완성 뒤 (사용자 10-24) | 아스트라 |

**데모 범위 (사용자 10-24)**

- 2층 판 + 두 번째 의뢰: 데모는 두 번째 현장까지 포함한다.
- 첫 현장 특별 현장: 사실상 튜토리얼로, 몰입의 시작과 히로인의 매력을 보여 준다. 현장 건설 마석을 넉넉히 줘 배치를 이리저리 바꾸는 재미를 느끼게 하고, 스토리·튜토리얼로 첫 의뢰 진행에 시간이 좀 걸리게 설계한다.
- 시설 강화: 현장 기본 화면에서 지어진 함정·대기실을 눌러 강화한다. 강화 항목·재화·납품 뒤 유지 여부는 기획서에서 정한다.
- 던전 카드 개편: 단순 수치 버프 위주에서 이벤트·출진·원군 등으로 넓히고, 선택한 뒤 효과가 확실히 보이게 한다.
- 화면 다듬기 2차: 건설 판 가시성과 튜토리얼 동선(결과표 [홈으로])을 다듬는다.
- 전투 결과 설명: 배치·경로와 결과의 관계를 한 줄로 알려 다음 배치를 바꿀 근거를 준다.

**사용자가 정할 것**

- 시설 강화 세부: 무엇을 올리고, 어떤 재화로 하며, 납품 뒤 무엇이 남는지는 기획서 작성 때 정한다.
- 경험치 책·훈련 교본: 용도는 나중 기획 단계에서 정한다.
