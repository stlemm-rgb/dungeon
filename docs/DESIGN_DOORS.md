# 설계: 문·경로·방 합치기 (초안, 2026-10-23)

> 사용자 피드백(`docs/GAME_PLAN.md` "건설 화면 2차 피드백" 절)을 규칙과 계산 방식으로 옮긴 총괄 초안. **핵심 재미 찾기 단계** → 숫자·연출은 나중. Codex 반박 뒤 사용자 확정.

## 0. 한 줄 요약
판 = **칸(1칸 = 1방) + 벽 + 문**. 침입자는 **보물방까지 가까워지는 문으로만** 움직인다. 문을 옮기면 "가까워지는 길"이 바뀌어 경로가 다시 계산된다. 이 계산 결과를 지금 코드가 쓰는 "구역 → 다음 구역 목록(EXITS)"으로 바꿔 넣으므로 **전투·예보·전투력 계산은 그대로** 쓴다.

## 1. 판의 모양 (데이터)
| 것 | 뜻 | 저장 |
| --- | --- | --- |
| 칸 | 층마다 5열 × 7행 (지금과 같음). 칸마다 어느 방에 속하는지 | `site.cells[층][행][열] = 방 id` |
| 방 | 칸 1개 이상. 처음엔 **1칸 = 1방**. 합치면 여러 칸 | 방 id, 종류(일반·입구·보물방·고정·특수) |
| 벽 | 서로 다른 방에 속한 이웃 칸 사이 경계. 같은 방 안에는 벽 없음 | 저장 안 함 (칸에서 계산) |
| 문 | 벽 한 조각(이웃 칸 두 개 사이)에 뚫린 통로 | `site.doors = ["층:행,열|행,열", …]` |
| 계단 | 층과 층을 잇는 고정 문 (옮길 수 없음, 2층 의뢰부터) | 판 정의에 고정 |

- 판(의뢰)이 **처음 방·문 배치**를 준다. 고정 구역(하역장 등)은 처음부터 여러 칸짜리 방이고 합치기·문 옮기기 불가.
- 칸 사이 숫자 표시(지금의 7·6·20)는 그 문을 지나는 인원으로 그대로 쓴다.

## 2. 규칙
| 규칙 | 내용 |
| --- | --- |
| 문 수 | 방 종류마다 **최소 문 수**를 표로 둔다: 일반 2 · 입구 1 · 보물방 1 · 고정 구역 = 판 정의대로 · 특수 방 = 그 방 정의대로. 나중에 방 종류가 늘어도 표 한 줄 |
| 길 끊김 금지 | 입구 → 보물방(열린 가장 깊은 층)까지 문으로 이어진 길이 **하나 이상** 있어야 함. 끊기는 놓기는 막고 이유 토스트 |
| 문 옮기기 | 문을 끌어 **같은 방의 다른 벽 조각**으로 옮긴다. 놓는 동안 경로가 실시간으로 다시 그려짐(미리보기). 규칙을 어기는 자리는 빨갛게, 놓으면 제자리 |
| 문 수 바꾸기 | 데모: 문은 **옮기기만**(수는 판이 준 대로). 문 추가·막기는 회사 레벨 해금 후보 |
| 방 합치기 | 이웃한 일반 방 두 개 사이 벽을 **두 손가락 대신 "합치기" 도구로 끌어 긋기**(제안) → 한 방이 됨. 그 벽에 있던 문은 사라짐. 합친 방도 최소 문 수 지켜야 함. 시설이 있는 방끼리는 같은 시설일 때만(큰 함정·큰 대기실) |
| 나누기 | 합친 방을 되돌리기. 데모에서는 미확정 상태일 때만 |
| 확정 | 문 옮기기·합치기는 시설 놓기처럼 **미확정 → [건설]로 함께 확정**. 비용: 문 옮기기 무료(제안), 합치기는 시설 값 규칙을 따름 |

## 3. 경로 계산 (알고리즘)
1. **방 그래프**: 방 = 점, 문 = 선(양방향). 계단 = 위층 방 → 아래층 방 한 방향.
2. **거리**: 보물방에서 거꾸로 너비 우선 탐색 → 방마다 "보물방까지 문 몇 개"(`dist`).
3. **다음 방 후보**: 지금 방의 문 너머 방 중 `dist`가 **더 작은 방만**. → 되돌아가거나 빙빙 도는 일이 없고, 지금 코드처럼 위에서 아래로 한 번씩 계산하는 순서(`ORDER`)가 나온다.
4. **EXITS 만들기**: 방마다 3의 후보 목록 = 지금의 `EXITS`. 이후 `chooseExits`(미끼 +2, 몬스터 든 대기실 -1, 점수 같은 쪽으로 번갈아 나눔)·`forecast`·`routeOf`·전투 시뮬레이션은 **고치지 않고** 쓴다.
5. **퍼즐이 생기는 이유**: 문 위치가 "가까워지는 길"을 정한다. 큰길 방의 아래 문을 옆 벽으로 옮기면 침입자가 곁방을 돌아가야 하고, 그 곁방에 함정을 두면 걸린다. 갈림 비율은 미끼·대기실로 조절(왼쪽·오른쪽 몰기).
6. **갈림 나누기·성향은 미정**: 4의 "번갈아 나눔"은 임시. 나중에 성향별 길 찾기를 **함수 하나로 갈아 끼울 수 있게** 둔다:
   - 기본(지금): dist가 줄어드는 문 중 점수 높은 쪽으로 번갈아
   - 광부(예시): 문 무시, 같은 열을 따라 **벽을 뚫고 일직선 아래로** (벽 뚫는 시간만큼 느림, 강화 벽이면 막힘 → 해금 요소와 연결)
   - 탐험가(예시): dist가 같은 방도 들름 → 곁방 함정에 더 걸림
7. **화면 경로 선**: `forecast().flow`(문마다 인원)로 방 중심 → 문 → 방 중심 선을 그리고, 인원이 많을수록 굵게. 미확정 상태도 같은 계산으로 미리보기.

## 4. 바뀌는 것 / 그대로인 것

## 5. 데모 범위 (제안)
- 1층 첫 의뢰: 1칸 방들 + 고정 구역 1개 + 처음 문 배치. **문 옮기기 + 경로 선**만 먼저 → 재미 확인.
- 그다음 **방 합치기**.
- 성향(광부 등)·문 추가/막기·다른 퍼즐 요소(일방통행 문·구덩이·이웃 시너지 등)는 회사 레벨 해금 후보로 적어만 둠.

## 7. Codex 반박 반영 (2026-10-23, 원문 `refs/codex_doors_critique_2026-10-23.md`)
| 지적 | 반영 |
| --- | --- |
| "가까워지는 길" = 실제로는 **문 개수 기준 최단 경로만**. 더 긴 곁방 길과 그곳 미끼는 무시됨 | 3절 규칙을 이렇게 고쳐 씀. 우회는 **짧은 길을 문으로 막아서** 만든다. 곁방까지 도는 이동은 **이동 규칙 B(탐험)**로 따로 두고 사용자 선택(아래) |
| 문 하나를 옮기면 **양쪽 방의 문 수가 같이 바뀜**(A-B → A-C면 B -1, C +1). 최소 문 수로만 짠 판은 합법 이동이 없을 수 있음 | 검사는 관련 방 전부 + **고립 방 없음** + 입구→보물방 연결. 문 수는 "판 전체 고정". 첫 판은 **문 3개 이상인 방과 실제로 가능한 이동이 여러 개** 있게 손으로 설계하고 시험으로 증명 |
| "EXITS만 바꾸면 그대로"는 과장: 입구 특례, 문 좌표 추정(sharedEdge), build.js가 EXITS에 없는 문을 안 그림 | 4절 정정: **실제 문 목록 · 문 좌표 · 이동 후보(EXITS)를 분리**. 전투 효과·함정·대기실 처리만 재사용 |
| 예보(forecast)는 사람 단위, 실제 전투(routeOf)는 분대 단위로 갈려 선과 실제가 다를 수 있음(7/7/6 vs 10/10/0) | **경로 선과 실제 이동은 같은 규칙·같은 단위로 계산**하게 고침 (임시 갈림 규칙이어도) |
| 합치기: 두 방 사이 경계·문 전부 사라짐, 합치면 새 지름길, 큰 방 내부 이동 선, 비용·시설·부대 합치기 미정 | 합치기는 2단계로 미루고 그때 따로 설계. 조작은 "합치기 도구로 두 방을 가로질러 긋기 + 합쳐질 영역 미리 표시" |
| 최소 실험 | **작은 1층 판, 시설 고정, 문 옮기기·경로 선·되돌리기만**. 같은 시드로 옮기기 전후 전투 비교. 성공 = 옮기기 전에 경로 변화를 예상하고 스스로 다른 배치를 시도함 |

## 8. 사용자 결정 (2026-10-23 밤)

## 9. 토론 결론 (총괄 + Codex, 사용자 확인 전) — 원문 `refs/debate_doors_2026-10-23.md`
| 항목 | 결론(제안) |
| --- | --- |
| 문 옮기기 | **P1 문 토큰**: 판 전체 문 N개(판마다 고정), 문을 집어 **아무 안쪽 벽에나** 놓음. 놓는 순간 옛 자리 닫힘·새 자리 열림을 한 번에 판정. 방마다 최소 문 수 없음. "회사 레벨로 문 +1"은 보류(문이 늘면 우회가 풀려 보상이 아닐 수 있음) |
| 전역 규칙 | 입구 → 보물방 연결 필수. **고립된 방은 허용**하되 그 안 시설은 전투 기여 없음(흐리게 표시) |
| 탐험 이동 | 분대마다 방문한 방 기록(분대끼리 공유 안 함). 갈림: 안 가 본 이웃 방 → 그중 미끼 센 쪽 → 같으면 **화면 기준 왼쪽·위·오른쪽·아래**. 막히면 들어온 방으로 되돌아가 남은 곳 확인. 보물방에 처음 들어가면 끝. 동점 갈림만 분대 번호순으로 번갈아 |
| 막다른 방 | "함정 두 번"은 자동이 아님(방 진입 때 발동) → 왕복 이득은 **같은 함정은 같은 분대에 최대 2회** 규칙으로 정함 |
| 꼼수 막기 | 분대별 왕복 포함 **문 통과 최대 18회**(넘는 배치는 확정 불가). 1분 초과는 방어 성공으로 치지 않음(시간 끌기 미로 방지) |
| 계산 구조 | 탐험은 방문 이력에 따라 다음 방이 달라짐 → "방마다 고정된 다음 방 목록(EXITS)" 재사용은 **버림**. 분대별 이동 목록을 만들어 경로 선과 실제 전투가 같이 씀 |
| 최소 실험 | 1층 **3 × 4 = 12방**, 입구·보물방 고정, 문 12개, 시설 고정(함정 2·대기실 1·미끼 1). 문 옮기기·경로 미리보기·되돌리기·실행만. 성공 = 경로 예측 7/9회 이상, 도움 없이 문 이동, 이유 있는 재배치. 실패 = 선만 따라 무작정 이동, **가장 긴 길이 늘 최선** |
| 총괄 추가 | 최소 실험은 D1에 바로 넣지 않고 **별도 실험 페이지**(`prototype/door_lab/`)로: 저장 형식·튜토리얼·전투력 계산을 안 건드리고 하루 이틀 만에 재미 확인 → 되면 D1에 옮김 |

## 10. 사용자 확정 (2026-10-23 밤)
- **P1 문 토큰** 확정. 9절의 바로잡은 내용(같은 함정 같은 분대 최대 2회, 문 수 판마다 고정·레벨 보상 보류, 문 통과 최대 18회·시간 끌기는 방어 성공 아님) 확정.
- **탐험가 이동 속도**: **빈 몬스터 대기실**(몬스터가 없거나 다 쓰러진 대기실)과 **그 분대가 한 번 가 본 구역**에서는 이동 속도 **1.5배**. 실시간 전투 중에만 쓰는 기록이고 전투가 끝나면 저장하지 않음.
- 최소 실험은 **별도 페이지** `prototype/door_lab/`. 만들기는 Codex 하청(사용자 요청).
