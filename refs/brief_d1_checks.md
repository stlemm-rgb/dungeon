## 맡는 파일
`tools/` 안 파일(새 파일 포함), `tools/shots/` 아래 **새 D1 기준 이미지**(새 폴더나 새 이름으로), `RUNBOOK.md`의 검사 안내 부분, PROGRESS.md.
`prototype/` 코드는 고치지 않는다(검사에 필요한 작은 훅이 꼭 필요하면 보고만). 옛 검사의 **기존 기준 이미지·정답지는 갱신하지 않는다**.

## 할 것
1. **D1 대사 검사**: `test_lines.py`가 `prototype/d1_demo/lines.js`를 보게 (튜토리얼 id 목록은 D1 것, 홈 이름 5명, 백틱·`${` 깨짐). C1 대사 검사는 옛 묶음으로 남기거나 함께 돌림(아래 4).
2. **D1 화면 사진 검사**: `shots.py`에 D1 화면 추가(390×844 중심 + 1280 하나): 회사(홈) · 현장 · 건설 모드 · 전투 중 한 장면(시드·시간 고정해 흔들림 없게) · 결과표. 가로 넘침 0, 콘솔 오류 0도 같이. 새 기준 이미지는 만들어 두고 **경로를 보고** (총괄이 눈으로 확인).
3. **D1 한 바퀴 검사** (새 파일, 예 `test_d1_flow.py`): 헤드리스 브라우저로 `?seed=` 새 게임 → 의뢰 고르기 → 건설 모드에서 **문 하나 끌어 옮기기 + 시설 하나 놓기 → [건설]** → 홈 → 다음 주 → 전투 끝까지(배속) → 결과표(요약 한 줄 있음) → 저장·새로고침 뒤 이어짐 → (API로 빨리 감아) 납품 → 데모 끝 화면. 콘솔 오류 0. 브라우저 구동은 기존 `tool_common`의 방식을 우선 쓰고, 끌기가 필요하면 `refs/cdp_helper.js` 방식을 tools 안으로 옮겨 써도 됨(옮기면 HANDOFF/참조 경로를 보고에 적기).
4. **check_all 정리**: 단계를 **D1(지금 데모)** 묶음과 **옛 게임(루트·C1)** 묶음으로 나눠 출력(둘 다 계속 돌림 — 옛 것 보관은 다음 일). `node prototype/door_lab/selftest.js`도 한 단계로 추가. node 없으면 지금처럼 건너뜀.
5. `RUNBOOK.md`의 검사 설명을 새 구성에 맞게.
