근거: 확정 기획서 `docs/specs/facility_upgrade.md`(5절 화면, 7절 끝 기준) · 로직은 끝남(PROGRESS 70) · 계약서 `prototype/d1_demo/API.md` **14절**(특히 14-5 "화면에 넘길 일"). 사용자 메모 1(HANDOFF): 현장 기본 화면에서 지어진 함정·대기실을 누르면 강화 화면.

## 맡는 파일
`prototype/d1_demo/` shell.js · shell.css · build.js · stage.js(판 그리기가 여기면). **로직 파일(progress.js·battle_sim.js·battle_data.js·zones.js)은 고치지 않는다.** 로직에 빠진 게 있으면 고치지 말고 보고에 적는다.
화면이 바뀌어 `py tools/shots.py --d1` 기준 사진이 달라지면 `--d1 --update`로 **D1 기준만** 갱신해도 된다(옛 기준 금지). 갱신한 사진은 스크래치 폴더에 복사해 경로를 보고.

## 1. 강화 창 (현장 기본 화면, 건설 모드 아님)
- 판에서 지어진 함정·대기실 방을 누르면 **아래쪽 상세 창**(판 위로 겹침). 값은 `P.upgradeInfo(방)`만 읽는다.
- 보여 줄 것(위→아래): 방 이름·시설 이름·단계(예: 2/3) → 효과 지금 → 다음(`effectNow.text`·`effectNext`, 최고면 "최고 단계") → 비용·남을 마석(`cost`·`budgetAfter`) → 예상 전투력 전→후(`powerNow`→`powerAfter`, 정수가 같으면 `powerGain`으로 "+0.4" 같이) → [강화] [닫기].
- 대기실: 출진 부대(`units`) 짧게 + "이 방에서만 적용". `noEffect`면 "출진 부대가 없어 효과 없음".
- `pass`가 낮으면(0.2 미만 정도) "이 방은 지나가는 침입자가 적어요 — 문 배치부터 바꿔 보세요". 예상치는 확정 결과가 아님을 작은 글로. **일반 화면에 경로 선 추가 금지.**
- 거절(`ok:false`)이면 [강화]를 흐리게 하고 `why`를 버튼 옆에(마석 부족·최고 단계 등). `code 'target'`·`'locked'`인 방은 창을 아예 열지 않아도 된다(빈 방·입구 등을 눌렀을 때 아무 일 없음이 자연스러움).
- [강화] = `P.upgradeFacility(방)` 한 번. 결과 뒤 창·판 단계 표시·마석 표시를 함께 갱신. **빠른 연속 누르기에 두 번 차감 안 되게**(누르는 동안 버튼 잠금 등). [닫기]·바깥 누르기 = 아무 함수도 안 부름.
- 휴대폰 390px: 선택한 방이 창에 가리지 않게(필요하면 판을 스크롤하거나 창 높이 제한), [강화]·[닫기]가 화면 안에 보이게. 가로 넘침 없음.

## 2. 판 단계 표시
- 강화된 시설 방에 작은 단계 표시(예: 아이콘 옆 "+1"/"+2" 또는 별 점). `P.upgradeLevel(방)`, 1이면 표시 없음. 현장 기본 화면과 건설 모드 판 모두.

## 3. 건설 미리보기
- 건설 모드에서 `previewLayout()`에 `upLost`·`refund`가 있으면 아래 합계 줄 근처에 "강화 사라짐 N곳 · 환급 +N" 표시. 확정 메시지는 `commitLayout().msg` 그대로.
- **건설 모드의 끌기와 강화 누르기를 섞지 않는다**: 건설 모드에서 시설을 눌러도 강화 창은 안 뜬다.

## 4. 튜토리얼
- 튜토리얼 진행 중 강화 창이 말풍선·반짝임과 겹치거나 흐름을 막지 않는지 확인. 강화 안내 말풍선을 새로 만들 필요는 없다(튜토리얼은 뒤로, 사용자 10-24).
