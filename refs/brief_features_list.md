# 지시서: 기능 목록표 초안 docs/FEATURES.md (Codex 하청 "솔", 2026-10-24)

## 고칠 파일 (이것만)
**새 파일 `docs/FEATURES.md` 하나.** 다른 파일은 고치지 않는다. 커밋하지 않는다.

## 목적
흩어진 기능·콘텐츠 아이디어를 **한 줄씩** 모은 지도. 다음에 무엇을 만들지 사용자가 고르는 데 쓴다. 상세 기획은 쓰지 않는다(넓고 얕게).

## 모을 곳 (읽기)
`docs/GAME_STRUCTURE.md`(탭·입구), `docs/CONTENT_IDEAS.md`, `docs/GAME_PLAN.md`(나중에·보류·데모 밖으로 적힌 것), `docs/DESIGN_DOORS.md`·`docs/DESIGN_D1_DOORS.md`(나중에 적은 퍼즐 요소), `HANDOFF.md`(사용자 메모·알려진 문제·다음 할 일), `refs/draft_*.md`, `새_게임_청사진.md`.

## 형식
맨 위 3줄 설명(이 파일의 역할, GAME_PLAN = 결정 일지 · CONTENT_IDEAS = 아이디어 창고 · FEATURES = 무엇을 언제 만들지 지도). 그다음 표 하나:

| 기능 | 분류 | 루프 어디 | 단계(추천) | 의존 | 상태 | 출처 |
| --- | --- | --- | --- | --- | --- | --- |
| 시설 강화 | 기능 | 매주 (건설 다음 선택) | 데모 | 마석 | 아이디어 | HANDOFF 사용자 메모 1 |

- **분류**: 기능 / 콘텐츠 / 화면 / 경제 / 메타
- **루프 어디**: 의뢰 고르기 · 건설(퍼즐) · 출진·군단 · 전투 · 납품·정산 · 회사 성장 · 메타(마계·내 집 등) · 루프 밖
- **단계(추천)**: 데모 / 출시 / 나중 — **추천일 뿐, 사용자가 정한다**. 데모는 최대 4개만 추천(지금 데모 = 1층 첫 의뢰 → 데모 끝, 2층 의뢰 숨김).
- **상태**: 끝 / 만드는 중 / 설계 있음 / 초안 있음 / 아이디어
- **출처**: 파일 이름(과 절). 이미 만든 것(문 토큰·탐험·조우 판정 등)은 상태 "끝"으로 짧게 넣는다.
- 같은 것은 한 줄로 합친다. 루프 순서대로 묶어 정렬. 40~70줄 안팎.

표 아래: **"데모 추천 4개와 이유"** 한 줄씩, **"사용자가 정할 것"** 최대 5개(예: 시설 강화가 무엇을 올리나).
