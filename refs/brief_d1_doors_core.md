## 할 것 (설계서 절 번호)
1. 2절 판 데이터 `GRID_BOARDS.g1` (5×7, 입구 C1 → 방 E, 보물방 C7 → 방 B, 고정 구역 1개, 처음 문 손 설계, 문 토큰 = 방 수 + 2 안팎).
2. 4-1 `exploreRoute` (실험 규칙 그대로, 대기실 "보여서 피함" 없음).
3. 4-2 battle_sim: 탐험 경로·문 가운데 지점·조사 0.6초·가 본 방 1.5배·함정 같은 분대 2회까지·**조우 즉시 승패**(11·12절: 힘 = 체력 × 공격 비교 ±20%, 진 쪽 퇴각·몬스터는 다음 주 쉼, 이긴 쪽 피해는 **체력 비율 + 상한**, 침입자 체력 절반 아래 퇴각, 시간 초과 = 방어 성공, 동시 조우는 분대 번호순, 그 분대만 2초 멈춤). 사건 `clash`·`inspect` 추가. 위기 카드는 전투 수치 카드만 승패 힘에 더함. 사망 판정 없음.
4. 4-3 전투력·passRatios·forecast·mustPass를 고정 시드 4개 × 습관 3 경로로.
5. 5절 API (`grid`·`edges`·`doorPoint`·`roomCenter`·`doorInfo`·`previewLayout`·`commitLayout`·`exploreRoutes`, `battleInput.doors`). 문 통과 한도를 넘는 배치는 **확정 불가**(code 'limit'). 결과에 "함정으로 N분대 퇴각, 대기실에서 N분대 격퇴" 요약 한 줄용 값.
6. 3절 저장 v7, 옛 v6 B안 바꾸기 + 검사.
7. 숫자는 6절 임시값(이동 1칸 2초, 한도 30 안팎, 시간 60초). **밸런스 맞추기는 하지 않는다**(12절). 대신 q1 안내 정책 측정표(주 수·보물방 도달률·시간 초과율·평균 전투 시간)를 battle_data.js 주석과 보고에 남긴다.

## 순서
API(5절)를 **먼저** 열고 검사 통과 → 중간 커밋 → 전투·저장 마무리. 중간 커밋 뒤 총괄에게 짧게 알릴 필요는 없다(끝에 한 번 보고).

## 끝 기준
- `py tools/check_all.py` 종료 코드 0 (파이프로 자르지 말 것). `shots.py` 기준 이미지가 화면 변화로 달라지면 **갱신하지 말고** 보고(총괄이 확인 후 갱신).

- 워크트리 브랜치에 커밋, push 하지 않음. 보고: 쉬운 한국어 표(바꾼 것·임시 숫자·측정표·화면 쪽에 넘길 API 변화·남은 문제).
