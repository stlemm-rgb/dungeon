# Codex 기획 토론 지시서 틀 (2026-10-21)

첫 토론(`debate_play_flow_2026-10-21.md`)에서 지시서가 브레인스토밍을 막았다. 그 반성으로 만든 틀이다.
- 그때 문제: "숫자 균형 제외·150줄·사용자 결정 존중" 같은 제한이 앞에 와서, 둘 다 기존 결정과 부딪치는 안을 스스로 지웠다. Codex는 "결정과 충돌"을 반대 이유로 썼고, 총괄은 답 없이 질문만 넘겼다.
- 바꾼 점: **발산(넓게 내기)과 수렴(좁히기)을 라운드로 나눈다.** 제한은 수렴 라운드에만 둔다.

## 1라운드: 발산
```
너는 모바일 인디 게임 기획 토론 상대다. <대상 문서·절>을 읽어라.
- 기존 사용자 결정도 고칠 수 있다. 더 나은 안이 있으면 "결정 변경 제안"이라고 표시하고 내라.
- "결정과 충돌한다"는 반대 이유가 아니다. 충돌한다면 어느 쪽이 더 재미있고 만들기 쉬운지로 판단해라.
- 구멍을 찾으면 질문으로 끝내지 말고 **추천 답 하나와 이유**를 함께 내라.
- 참고 게임(던전 경영, 모바일 성장 게임)의 흔한 방식도 끌어와라.
- 아이디어 수와 길이는 제한하지 않는다.
```

## 2라운드: 반박·합치기
- 총괄이 상대 안에 수용·반대·합치기를 붙이고, 새 안을 더한다.

## 3라운드: 수렴 (여기서만 제한)
- 1인 개발 비용, 지금 단계(균형 없이 기능 위주), 길이 제한을 적용한다.
- 결과 표는 항목 | 추천 답 | 바뀌는 사용자 결정(있으면) | 확인 필요.

## 총괄이 사용자에게 가져갈 때
- 열린 질문만 넘기지 않는다. 항목마다 **총괄 제안**을 붙이고 사용자는 확인하거나 고르기만 한다.
- 구현은 사용자가 확정한 뒤에만 한다.
