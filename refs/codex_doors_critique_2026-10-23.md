# Codex 반박: 문·경로 설계 초안 (2026-10-23)

> 대상 docs/DESIGN_DOORS.md 초안. 읽기 전용 하청, 총괄 검수. 반영 결과는 DESIGN_DOORS.md 7절.

**문 옮기기와 경로 선을 먼저 검증하는 순서는 좋습니다. 다만 지금 초안은 ‘우회를 만드는 재미’와 ‘실제로 문을 옮길 수 있는지’를 충분히 보장하지 못합니다.** 가장 위험한 부분은 최단 경로 규칙 자체보다, 문 수 제약과 결합했을 때입니다.

**1. `dist` 감소 규칙: 안전하지만, 우회로를 강하게 제한합니다.**

| 쟁점 | 판단 |
|---|---|
| 정확한 뜻 | ‘보물방에 가까워짐’보다 **‘남은 문 개수가 최소인 길만 선택’**이 정확합니다. 모든 선택 경로가 문 개수 기준 최단 경로가 됩니다. |
| 곁방 우회 | 가능합니다. 다만 **남아 있는 짧은 길을 모두 없애야** 강제할 수 있습니다. 미끼도 최단 경로 후보에서 빠진 곁방으로는 유인하지 못합니다. |
| 퍼즐 깊이 | 길을 바꾸는 퍼즐은 성립하지만, ‘지름길 제거 → 함정 늘어놓기’가 반복되는 정답이 될 위험이 있습니다. |
| 이동 중 막힘 | 보물방에 연결되어 있고 거리 계산이 정확하면 막히지 않습니다. 목표까지 가는 다음 문이 항상 있습니다. |
| 직관 | 화면상 가까운 방향과 남은 문 개수가 다를 수 있습니다. **문을 옮겼더니 멀리 떨어진 갈림의 선택도 바뀌는 것**은 설명 없이 이해하기 어렵습니다. |

선은 문 연결, 그리지 않은 경계는 벽입니다. `E`는 입구, `G`는 보물방입니다.

```text
① 긴 우회로는 무시됨

E──A──B──G
   │  │
   C──D
```

`A`의 dist는 2, `C`는 3입니다. 따라서 `A→C→D→B`는 선택되지 않습니다. **C에 미끼를 놓아도 효과가 없습니다.** 현재 외길 판에는 `R2→R3`와 `R2→NL2→R3`가 함께 있는데, 새 규칙에서는 긴 곁방 길이 사라집니다.

```text
② 방마다 문 2개 이상이어도, 곁구역 전체가 막다른 길

E──A──G
   │
   B──C
   │  │
   D──F
```

모든 일반 방이 문 2개 이상이고 입구부터 보물방까지 연결되어 있습니다. 하지만 아래 고리는 **A로 돌아와야만 빠져나올 수 있어** 새 규칙에서는 아예 들어가지 않습니다.

즉, **이동 중 막히지 않는 것과 판에 쓸모없는 곁구역이 없는 것은 별개**입니다.

**2. 대안 이동 규칙 비교**

| 규칙 | 퍼즐 깊이 | 예측 가능성 | 구현 난이도 | 기존 EXITS·ORDER 재사용 |
|---|---|---|---|---|
| **초안: 최단 경로만** | 중간. 지름길 차단 중심 | 높음. 거리 기준 설명 필요 | 낮음 | 가장 높음 |
| 미방문 방 우선 탐색, 막히면 되짚기 | 높음. 곁방·탐색 순서 활용 | 고정 문 우선순위가 있으면 높음 | 중간~높음. 방문 기록·되짚기 필요 | 전투 효과 일부 재사용. 현재 ORDER 예보는 교체 |
| 오른손 법칙 | 중간~높음. 진입 방향·문 배치 활용 | 규칙은 단순하나 큰 방에서는 복잡 | 중간~높음. 진입 방향·반복 상태 처리 | 문 그래프는 재사용. ORDER는 교체 |
| 무게 있는 무작위 | 선택지는 많지만 퍼즐 해법이 흐려짐 | 낮음. 고정 시드면 같은 결과 가능 | 중간~높음. 반복·도달 처리 필요 | 점수 계산 일부 재사용. ORDER는 교체 |

- **‘지난 방은 다시 안 감’만으로는 깊이 우선 탐색이 아닙니다.** 잘못 들어간 뒤 빠져나오지 못할 수 있으므로 되짚기가 필요합니다.
- 오른손 법칙과 무작위도 일반적인 고리 구조에서 보물방 도달을 자동 보장하지 않습니다.

**이번 실험에서는 최단 경로 규칙을 임시로 유지하는 쪽을 추천합니다.** 비교 구현까지 벌리기보다, 이 규칙 아래서 문 이동이 충분히 재미있는지 먼저 확인하는 편이 1인 개발에 유리합니다.

**3. ‘일반 방 문 2개 이상 + 문 개수 고정’의 가장 큰 함정**

| 상황 | 영향·보완 |
|---|---|
| `A-B` 문을 `A-C`로 이동 | A의 문 수는 같지만 **B는 −1, C는 +1**입니다. A만 검사하면 안 됩니다. |
| B의 문이 정확히 2개 | 이동 뒤 1개이므로 금지됩니다. **최소 문 수로만 짠 외길 판은 연결 대상을 바꾸는 단일 이동이 전부 막힐 수 있습니다.** |
| 합친 방에서 같은 이웃으로 문 2개 | 물리적인 문은 2개지만 출구가 같은 방뿐이면 막다른 구조일 수 있습니다. |
| 문 2개짜리 고리 | 고립된 고리도 가능하고, 위 반례처럼 한 곳으로만 붙은 곁구역도 가능합니다. |
| ‘수는 고정’의 뜻 | **이동 시 판 전체 문 수 고정**인지 명시해야 합니다. 방별 문 수까지 고정하면 허용되는 조작이 훨씬 줄어듭니다. |

최소 문 수는 유지하되, **첫 판에는 문 3개 이상인 방과 실제로 가능한 이동을 의도적으로 배치해야 합니다.** 입구→보물방 연결 검사에 더해 일반 방의 고립 여부도 확인해야 합니다.

**4. 합치기 조작과 규칙의 함정**

| 함정 | 초안에 필요한 보완 |
|---|---|
| ‘벽을 긋기’가 벽 생성처럼 느껴짐 | 합치기 도구로 **두 방을 가로질러 긋고**, 합쳐질 전체 영역을 미리 표시하는 편이 명확합니다. 한 번에 두 방만 처리합니다. |
| 긴 경계를 일부만 지움 | 두 방을 합치면 **두 방 사이의 모든 경계와 내부 문**이 사라져야 합니다. 그은 부분만 지우면 방 정의와 그림이 달라집니다. |
| 문 수 고정과 충돌 | ‘문 이동은 개수 유지, 합치기는 내부 문 삭제’라는 예외를 명시해야 합니다. |
| 합치면 경로 선택도 바뀜 | 두 방이 한 방이 되면 문 통과 횟수가 줄어 **새 지름길**이 됩니다. 시설 크기 변경만의 문제가 아닙니다. |
| 시설·부대·비용 | 시설+빈 방의 처리, 추가 칸 비용, 부대 목록 통합이 미정입니다. 같은 시설끼리 합칠 때도 기존 비용을 중복 청구하면 안 됩니다. |
| 큰 방 내부 이동 | ㄷ자 같은 방의 평균 중심은 방 밖일 수 있습니다. 중심→문 직선이 벽을 관통할 수 있어 실제 내부 경로가 필요합니다. |
| 확정 뒤 나누기 불가 | 경로 변화와 비용을 모두 미리 보여 주고, 미확정 상태에서는 합치기 전체를 되돌릴 수 있어야 합니다. |

현재 `trapDmgOf`는 방 칸 수에 비례하고 전투에서는 방 진입 시 함정이 발동합니다. **합치기 전후 같은 면적이라고 전투 효과까지 같아지는 것은 아닙니다.**

**5. 데모 순서는 맞습니다. 최소 실험은 하나면 됩니다.**

**작은 1층 판 하나에서, 시설은 고정하고 문만 옮겨 ‘함정 → 대기실’ 순서로 유도하게 해 보세요.**

| 항목 | 최소 구성 |
|---|---|
| 판 | 1칸 방 중심의 손설계 판. 일반 방 최소 문 수를 지키면서 **의미 있는 합법 이동을 여러 개 확보** |
| 조작 | 문 이동·경로 선·되돌리기만. 합치기는 다음 단계 |
| 비교 | 같은 침입자와 같은 시드로 편집 전후 전투 비교 |
| 확인할 것 | 플레이어가 옮기기 전에 경로 변화를 예상하는지, 결과를 보고 이유를 설명하는지, 다른 배치를 스스로 시도하는지 |
| 실패 신호 | 빨간 금지 위치만 반복해서 만나거나, 선이 바뀌는 모습을 무작정 따라가며 정답을 찾음 |

최장 경로가 항상 이기면 시설 종류를 추가하기 전에, **현재 이동·전투 규칙만으로 선택의 손익이 있는지**부터 재검토해야 합니다.
